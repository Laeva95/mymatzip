정범석 · 역할: (C 코스)
1. 내가 맡은 일 

맛집탐방 프로젝트에서 리뷰·별점 기능을 맡았다. 회원이 맛집에 리뷰와 1~5점 별점을 쓰고, 사진을 첨부하고, 삭제하고, 신고할 수 있는 REST API를 Controller → Service → Repository 구조로 만들었다. 리뷰에 답글을 다는 기능과 리뷰 목록 페이징, 맛집별 평균 별점 계산도 구현했다. 발견한 결함(없는 ID 삭제, 본인·중복 신고, 이미지 경로 검증, 페이징)을 재현하는 테스트 코드를 작성했다.

2. 주요 구현 파일 목록
   ① 엔티티 (Entity)
   entity/Review.java: 리뷰 내용(content), 별점(rating), 작성자(member), 대상 맛집(restaurant), 이미지 경로(imageUrl), 신고 여부(reported) 매핑
   entity/Reply.java: 리뷰에 종속되는 답글 내용(content), 작성자(member), 대상 리뷰(review) 매핑
   ② 리포지토리 (Repository)
   repository/ReviewRepository.java: 맛집별 최신순 조회, 평균 별점 계산(@Query AVG), 페이징 조회, 신고된 리뷰 조회
   repository/ReplyRepository.java: 특정 리뷰의 답글 오래된 순 조회(@EntityGraph 적용), 회원별 작성 답글 조회
   ③ DTO (Data Transfer Object)
   dto/ReviewForm.java / dto/ReviewResponse.java: 리뷰 입력값 유효성 검증(@NotBlank, @Min(1), @Max(5), @Size(max=1000))과 이미지 경로 검증(imageUrl: @Size(max=500), @Pattern) 및 응답 데이터 변환
   dto/ReplyForm.java / dto/ReplyResponse.java: 답글 입력값 유효성 검증(@NotNull, @NotBlank, @Size(max=500)) 및 응답 데이터 변환
   ④ 서비스 & 컨트롤러 (Service & Controller)
   service/ReviewService.java: 리뷰 목록 조회(전체·페이징), 작성, 작성자·관리자 확인 후 삭제(사진이 있으면 image 기록 소프트 삭제), 평균 별점 반올림 처리, 리뷰 신고 처리(본인 리뷰·중복 신고 차단)
   service/ReplyService.java: 답글 목록 조회, 작성, 작성자·관리자 확인 후 삭제 처리
   controller/api/ReviewApiController.java / ReplyApiController.java: 리뷰 및 답글 REST API 엔드포인트 제공 (401 비로그인, 403 권한 없음, 404 없는 대상 구분)
   ⑤ 화면 (Template)
   templates/restaurant/detail.html: 맛집 상세의 리뷰 영역 (작성, 삭제, 신고, 리뷰 사진 첨부·미리보기·업로드). 사진은 /api/files/uploadfors3only (folder=review)로 업로드한 뒤, 반환된 경로를 imageUrl로 담아 리뷰를 등록한다.
   ⑥ 테스트 (Test)
   test/.../review/IssueVerificationTest.java: 결함 4~7번 재현 테스트
   4: 없는 리뷰·답글 삭제 시 404
   5: 본인 리뷰 신고, 중복 신고 차단
   6: imageUrl 길이(500자 초과)·형식 검증, 정상 경로(/api/files/review/UUID.jpg) 등록 201, 폴더 없는 경로 400
   7: 리뷰 목록 페이징(page, size) 적용
3. 내가 겪은 문제
   문제: 없는 ID를 삭제해도 403이 나간다.
   원인: 모든 IllegalArgumentException을 403으로 일괄 처리했다.
   해결: 없는 대상은 404, 권한 없음은 403으로 나누어 응답하도록 했다.
   문제: 사진을 붙여 리뷰를 등록하면 400("올바른 이미지 경로 형식이 아닙니다.")이 난다.
   원인: 리뷰 화면이 폴더가 없는 경로(/api/files/UUID.jpg)를 돌려주는 기존 업로드 API(/api/files/upload)를 호출하고 있었는데, ReviewForm의 imageUrl 검증은 /api/files/review/UUID.jpg 형식만 허용했다. 기존 테스트는 잘못된 값이 400인지만 확인해서 이 문제를 잡지 못했다.
   해결: 업로드 API를 /api/files/uploadfors3only로 바꾸고 folder=review를 함께 보내도록 수정했다. 정상 경로는 201, 폴더 없는 경로는 400이 나는지 확인하는 테스트를 추가해 재발을 막았다.
